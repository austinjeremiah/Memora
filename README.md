# MEMORA

**Persistent clinical memory with a deterministic safety gate.**

A receiving clinician inherits a patient with years of history and ten minutes
to read it. They ask an AI to summarise. The AI writes *"renal function is
stable, no outstanding concerns"* — fluent, confident, and entirely invented.

MEMORA remembers a patient's history in [Sibyl Memory](https://docs.sibyllabs.org/memory/)
across process death, and **structurally cannot** let a model turn an
unsupported or unauthorised claim into trusted clinical output.

> ⚠️ **Synthetic patient data only.** Every patient is generated by
> [Synthea](https://github.com/synthetichealth/synthea). Nobody in this system
> ever existed. A research prototype — not for clinical use, not certified for
> any regulatory standard.

## Where memory is written and read

The rules ask that a judge find this in under two minutes. Two files:

| | |
|---|---|
| **[`backend/memora/sibyl/client.py`](backend/memora/sibyl/client.py)** | Every Sibyl read and write in the project. Nothing else imports `sibyl_memory_client`. |
| **[`backend/memora/sibyl/preflight.py`](backend/memora/sibyl/preflight.py)** | The guard that makes memory load-bearing rather than decorative. |

```python
# preflight.py — asserted BEFORE the client is ever constructed
def assert_store_available(db_path: Path) -> None:
    if not db_path.exists():
        raise SibylUnavailableError(
            f"Sibyl memory store not found at {db_path}. MEMORA cannot "
            "reconstruct patient context without it and will not answer "
            "from anything else."
        )
```

**Why that guard exists.** `MemoryClient.local()` **silently recreates** an
empty store when `memory.db` is missing — verified by execution:

```
deleted memory.db.  exists: False
REOPEN: NO RAISE - client constructed fine
        db recreated: True
        list_entities: []   read_events: []
```

Without checking before the client is constructed, MEMORA would have answered
HTTP 200 with an empty brief and **failed the load-bearing criterion while
every test stayed green.** Now it refuses:

```
$ rm memory.db
$ curl -X POST localhost:8000/handoff -d '{...}'
503  {"error":"sibyl_unavailable","detail":"Cannot reconstruct patient context…"}
```

Automated in [`tests/compliance/test_deletion.py`](backend/tests/compliance/test_deletion.py),
as stage 9 of [`scripts/e2e_full.sh`](backend/scripts/e2e_full.sh), and runnable
in the browser at **`/app/proof`**.

## How memory made this possible

Four things MEMORA does that are only possible because memory persists and is
structured.

**1. Cold-start recall.** Session one writes a patient's history and the process
exits. A genuinely new process — different PID, no shared state — reconstructs
everything from `memory.db` alone. Nothing but the file connects them.

**2. Trajectories, not snapshots.** A single lab result is a number. The same
store holding *every* result is a different clinical fact:

```
Heart rate    97 → 91 → 84 → 73 → 73  /min   falling, delta −24   LOINC 8867-4
Body weight   25.8 → 28.4 → 30.6 → 34.2 → 38.8  kg   rising, +13.0
```

Repeated observations are folded into a WARM entity carrying direction, delta
and the full series. That is a *dynamic storage pattern*: what is stored is
computed from history, not copied from the last write.

**3. Situational retrieval from one store.** The same patient, the same file,
three clinical questions, three different answers. `compile_plan()` is a pure
function — same inputs, same plan, every time — so this is true by construction
rather than true in the demo script.

**4. Sentinel — memory watching itself.** The reactive path reads WARM facts as
current truth and never asks whether the journal agrees. Sentinel asks exactly
that: a medication recorded as `active` while the journal holds a documented
adverse reaction to it. **Both sides came from the same store; they cannot both
be right.**

Sentinel reads and writes **its own memory** — a digest of findings under a
reserved tenant — so a finding is announced once and then tracked as
`PERSISTING` rather than re-alerting. That self-referential read/write is the
strongest coordination pattern in the project. **No model runs anywhere in that
path.**

## How it works

```
  Synthea FHIR ──► ingestion ──► Sibyl Memory (SQLite + FTS5)
                                   │
                          [ process dies ]
                                   │
                          [ new process ]
                                   ▼
REACTIVE                                  PROACTIVE — SENTINEL
────────                                  ────────────────────
Context Engine  situation+role→plan       WARM change / drift sweep
      │                                          │
Groq proposes claims                      EvidenceCheck built directly
      │                                   from the persisted record
Evidence Resolver checks each             NO LLM IN THIS PATH — ever
      │                                          │
      └──────────────┐          ┌────────────────┘
                     ▼          ▼
              DETERMINISTIC GATE
          evidence → authority → policy
                     │
        ALLOW / NEEDS_REVIEW / BLOCK
                     │
          clinician approval
                     │
        EIP-712 signature ──► Base Sepolia
```

**The model proposes; it never decides.** An unsourced claim is rejected on that
basis alone, however well it reads. `ALLOW` is reachable only when
`evidence.supported` is true, and only a real Sibyl read sets that.

## Partner stacks

**Base** — two contracts on Base Sepolia (chain 84532), both exercised:

| Contract | Address |
|---|---|
| `Commitment` | [`0x8B289101a7d6Bd7d066526B7b8D899Df582dd6b5`](https://sepolia.basescan.org/address/0x8B289101a7d6Bd7d066526B7b8D899Df582dd6b5) |
| `Attestation` (EIP-712) | [`0xc54122E46DDbF4F88a8D23d32586DC1cB0d8888e`](https://sepolia.basescan.org/address/0xc54122E46DDbF4F88a8D23d32586DC1cB0d8888e) |

An approved handover is hashed and anchored. `Attestation` records a clinician's
EIP-712 signature over typed data — `stateHash`, `evidenceRoot`, `contextHash`,
`memoryVersion` — with nonce and deadline replay protection the contract
enforces (EIP-712 provides none on its own). Built on OpenZeppelin's audited
`EIP712` / `Nonces` / `ECDSA`.

**No patient data ever goes onchain** — only a one-way digest, and a label
containing a synthetic Synthea identifier. Asserted in
`test_no_clinical_detail_reaches_the_payload`.

The signer and the relayer are **different addresses**: a wallet signs, the
server pays gas. The signature proves who approved; the relayer proves nothing.

> **Base is tamper-evident and publicly verifiable — not "immutable."** Nothing
> on a blockchain is mathematically immutable; it is computationally infeasible
> to alter undetected. The true claim is the stronger one.

## Running it

```bash
# 1. generate synthetic patients (needs Java 21)
cd vendor/synthea
java -jar synthea-with-dependencies.jar -p 40 --exporter.fhir.export true \
     --exporter.baseDirectory ./output Massachusetts

# 2. backend
cd backend
python3 -m venv .venv && ./.venv/bin/pip install -e ".[dev]"
cp .env.example .env          # add LLM_API_KEY (Groq) and BASE_PRIVATE_KEY
./.venv/bin/python scripts/ingest_demo.py ../vendor/synthea/output/fhir 3
scripts/run_api.sh            # :8000

# 3. frontend
cd frontend && npm install && npm run dev   # :3000 → /app
```

**Tests.** No mocks anywhere — every test runs against a real on-disk Sibyl
store, real Groq calls, and real Base Sepolia transactions.

```bash
cd backend
./.venv/bin/python -m pytest tests/ -q                        # 285, needs keys
./.venv/bin/python -m pytest tests/ -q -m "not llm and not chain"   # 273, offline
bash scripts/e2e_full.sh      # 9 stages, each a separate OS process
cd contracts && forge test    # 18 Solidity
```

Contract tests need submodules: `git clone --recursive`, or
`git submodule update --init`.

## Design decisions worth knowing

**No mocks, anywhere.** No mocking library is installed. This is not
fastidiousness — the original plan's *mocked* gate test returned
`{"status": "contraindicated"}` as an entire record and passed green, while the
real code read an unset column and the policy rule **could never fire**. The
mock encoded the assumption and hid the bug.

**Eight SDK contract corrections found by running the dependency**, not reading
its docs: `get_entity` raises rather than returning `None`; entity getters
return the row so payload is under `body` and lifecycle in the `status` column;
`write_event` is keyword-only; `read_events` truncates at 50; the real free-tier
cap is **5,242,880 bytes, not the documented 2 MiB**; `list_entities` exists.

**Structural matching, never substring.** Evidence links on stored
`(related_kind, related_name)` pointers. Substring matching over-matches — one
drug's history vouching for another whose name it contains — and silently
under-matches when phrasing changes.

**Row count drives store size, not payload.** Measured: 999 journal rows held
410 KB of content inside a 4.3 MB database, because SQLite plus four FTS5
indexes cost roughly 10× the payload. Retention is therefore per-record, which
keeps full clinical detail while fitting three patients in 67% of the cap.

Full per-phase build log in [`docs/phases/`](docs/phases/).

## Prior work

> The deterministic evidence/policy/authority gate pattern was conceptually
> inspired by Sibyl Labs' own publicly documented **Sibyl Sovereign** pillar
> (`sibyllabs.org`): *"You declare the rules the agent must follow, and a
> deterministic gate enforces them between the model and every action. A
> rule-breaking action never runs. The model can be wrong. The gate can't."*
> MEMORA implements that pattern independently, in Python, scoped to clinical
> claims rather than agent actions in general.
>
> The EIP-712 attestation uses **standard Ethereum tooling** — OpenZeppelin's
> audited `EIP712`, `Nonces` and `ECDSA`. No novel cryptography is claimed; the
> contribution is applying typed-data attestation to clinician approval of a
> memory-verified clinical state.
>
> Patient data is generated by **Synthea** (MITRE, Apache-2.0). Memory is
> **Sibyl Memory** (`sibyl-memory-client`, MIT). The landing page is built on a
> commercially licensed Framer template.
