# Phase F2 + F3 — Client layer, patients, and the memory explorer

**Status:** done · frontend only (backend unchanged — Phase B added the endpoints)

Built together because F2 alone is invisible: it exists so F3 can happen.

---

## F2 — the client layer

`lib/api/types.ts` (366 lines) and `lib/api/client.ts` now cover **all 14
backend routes**. Types were generated by dumping the backend's real Pydantic
models field-for-field, not by reading the Python by eye.

**Three functions that used to throw are now real:**

```ts
listPatients()        // was: "the backend has no GET /patients endpoint"
getPatientMemory()    // was: "no patient-history endpoint"
verifyCommitment()    // was: "exists in routes.py, just not wired here"
```

New: `getPatientContext`, `runSentinel`, `sinceLastReview`,
`getAttestationPayload`, `attestHandoff`, `verifyAttestation`.

`ApproveRequest` gained the optional wallet fields (`signature`, `signer`,
`issued_at`, `expires_at`, `nonce`) so F7 can use wallet mode without changing
the client again.

## F3 — patients and the memory explorer

### `/app/patients`

Real UUIDs read from the store. Each card shows fact and event counts, memory
version, kind breakdown, and a drug-allergy flag.

### `/app/patients/[patientId]` — the raw record

The page that makes persistent memory **inspectable rather than asserted**:

- **Lab trajectories** — inline SVG sparklines, direction, delta, LOINC codes.
  Only tests with ≥2 readings, because a single value is not a trajectory.
- **Facts by kind** — expandable tables showing the real coding systems
  (RxNorm, SNOMED, LOINC) rather than raw JSON.
- **The journal** — append-only, newest first, severity dots, and `source_id`
  provenance tracing each event back to its original FHIR resource.

Deliberately distinct from `/handoff`, which shows one situation's filtered
view. This shows what is actually stored.

## The hardcoded patient is gone for good

`lib/config/demo-data.ts` no longer exports `PATIENTS`. It previously shipped
`P-10482` — a fixture id from the backend's own scripts — with a comment
admitting it was unverified. It would 404 against any real store, because real
ids are Synthea UUIDs generated per ingestion run.

A shared `components/app/PatientPicker.tsx` reads live from `GET /patients`, so
no page can reintroduce one. `handoff/new` and `compare` both use it.

## Honest gaps

**One genuinely static list.** `SITUATIONS` in `demo-data.ts` is three hardcoded
values because no backend endpoint exposes the `Situation` enum. The settings
page says so on screen. A `GET /situations` endpoint would close it.

## A note for whoever debugs this next

Deleting `.next` while a dev server is running makes every route return 500
until it restarts. That is not a code fault. `rm -rf .next && npm run build`
is safe; doing it under a live `npm run dev` is not.
